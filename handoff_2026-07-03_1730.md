## 1. What this project is

**Vision:** make CLI coding agents (Claude Code, OpenCode) treat money the way a
human engineer treats time — every LLM call costs real dollars; if the agent can
see a real, depleting dollar budget, it should start making economic decisions:
stop unproductive exploration, prefer cheap actions, ship when good enough.

**Hard invariants (do not violate):**
- **Cost is MONEY.** Real USD computed from token usage × retail prices. Never a
  proxy (tool-call counts, turns, iterations). Free-tier models are priced at the
  paid model's retail rate so pressure stays real.
- **Advisory only.** The daemon NEVER blocks a tool call, never aborts a session,
  never enforces a ceiling. It injects the true number; the model decides. Even
  at $0 remaining the model may continue — user explicitly confirmed this is
  intended ("we trust the model; the task might be worth it").
- **Never ask the model to self-estimate its own budget cold** — documented
  failure mode (BAGEN paper: models systematically optimistic, tuned 7B model
  only 47% accurate). Budgets come from config/user/measured history.

**Two adapters, two capture mechanisms:**
- Claude Code = **pull**: bash hook (registered for SessionStart/PreToolUse/
  PostToolUse/Stop) POSTs hook payload incl. `transcript_path`; daemon parses the
  transcript for new assistant turns (usage blocks) on every hook fire. Injection
  channel = `hookSpecificOutput.additionalContext` (MUST be wrapped exactly like
  that or CC silently drops it). This channel ACCUMULATES in the conversation.
- OpenCode = **push**: TS plugin posts real usage from `message.updated` events
  (cumulative per message id → daemon does latest-wins UPSERT). Injection channel
  = `experimental.chat.system.transform` (`output.system.push`) — REBUILT on
  every LLM call, nothing accumulates.

**Injection policy (implemented this session — understand before changing):**
- Accumulating channel (CC): `inject_mode: "on_change"` — tracker re-injected
  only when tier changes or spend crosses another 10% budget slice
  (`inject_spend_bucket_pct`). Reason: per-tool-call injection measurably added
  +44% session cost. Over 100% budget, cadence coarsens to one bucket per
  half-budget overspent.
- Rebuilt channel (OpenCode; also stateless ReAct harnesses): client sends
  `channel: "rebuilt"` on /tool/pre → ALWAYS gets the tracker (suppressing would
  delete the budget from context), but the text is byte-stable: spend quantized
  to bucket floor, `~$` prefix, per-call tool counter omitted. Reason: any byte
  that changes per call invalidates the provider prompt cache — measured on
  deepseek: exact per-call text halved cache-hit rate (72%→44%) and cost +92%.
- Every DELIVERED injection is recorded in the `injections` table.
  `GET /session/<id>/dump` exports a session's full history (usage, tools,
  injections, plan) — runs are replayable from the daemon DB alone.

## 4. Experiment results (committed: `experiments/real_cli/RESULTS.md`, `analysis.json`)

**Claude Code (budget $0.18):** ON vs OFF = +2.8% cost, NOT significant
(t=−1.20). Injection now ~free (3.4 injections/run vs 22 before). All four tiers
observed escalating live in-session (HIGH→MEDIUM→LOW→CRITICAL — so the
cc_adapter-era claim "spend is frozen in-session" was overstated; lag is ≤1
turn). The ONLY question where ON saves money is q5 — the runaway-prone one
(same q5 as hotpotqa). **Conclusion: advisory budget does not cut required
work; savings live exclusively in discretionary/runaway work.**

**OpenCode / deepseek (budget $0.0025):** plumbing fully proven (plugin loads,
usage pushed+deduped, retail pricing, tiers delivered). Model behavior FLAT —
deepseek ignores guidance entirely (consistent weak-model non-compliance across
all experiments). Harness cache-bust tax found and partially fixed (see §2/§5).
Absolute overhead $0.00185/question — the scary % is because deepseek is ~80×
cheaper than Sonnet.

**Three-experiment consistent picture:** capable models respect the
required-vs-discretionary boundary; weak models ignore budgets; the harness's
own injection cost must be engineered to ~zero or it eats the benefit.

## 5. Known open issues / limitations (documented, not hidden)

- **Residual cache tax on rebuilt channel at sub-cent budgets:** one deepseek
  call ≈ 20% of a $0.0025 budget → even quantized text changes nearly every
  call. Possible fix: auto-widen bucket when observed per-call cost ≥ bucket.
- **Unknown model prices as $0** (`cost.price_for_model` → None → cost 0.0).
  This is a CHEAT CHANNEL (see §7 item 1) — top of the next-work list.
- **CC subagent spend** (Task tool children have separate transcripts) — likely
  UNMEASURED. Unverified. Also on the next-work list.
- **ai-title cost invisible:** CC's haiku title-generation calls write no usage
  block; ~constant per session; up to ~12% of LLM cost on very cheap sessions.
- **OpenCode cache-write 5m/1h split absent** from its payload → priced at 5m
  rate (conservative undercount).
- **Planning/Self-Verification/streak machinery**: never demonstrated value in
  any experiment. Candidate for deletion (next-work item 10).

## 6. Design principles for the NEXT phase (agreed with the user — read carefully)

The user rejected "naive engineering": no per-tool cost prediction tables, no
Python rule-based behavior detectors. Reasons (user's own examples):
- Ex-ante tool pricing is a whitelist: any unlisted tool (websearch, arbitrary
  MCP servers) is effectively free → the model routes spend through the
  unpriced channel. Unmaintainable AND gameable.
- Rule-based dead-end detectors are always incomplete → model behavior the
  rules miss is invisible → same cheat dynamic.

**Agreed philosophy:**
> The harness does ONLY what the model cannot: measure real money perfectly and
> COMPLETELY, and deliver it at the right moments. ALL judgment — estimating,
> planning, waste detection, deciding to stop — is the MODEL's job, prompted
> with true numbers. Never predict costs. Never detect behavior with rules.
> Measurement completeness IS the anti-cheat: every tool's output becomes
> context tokens, and tokens are measured ex-post, so nothing is free.

**UX principle:** one number from the user, maximum. "I have $10 for my
project, help me finish." No per-task estimates, no forms. Power users wanting
per-subtask budgets just launch a fresh instance with a smaller number.

## 8. Operational gotchas (these cost hours this session — do not relearn)

- **`pkill -f` self-match:** a `bash -c` script whose text contains the kill
  pattern kills ITSELF (exit 144). Split kill and relaunch into separate shell
  invocations; prefer collecting PIDs with `pgrep -f 'pattern\.py'` (the
  literal backslash prevents self-match) then `kill` by PID.
- **Daemon loads config ONCE at import** (`_config = load_config()` in
  daemon.py). Changing config.json requires a daemon restart — experiments do
  set_condition() + restart_daemon(). Backlog item 2 removes this pain.
- **OpenCode resolves its project root from the `PWD` env var, not the real
  cwd.** `subprocess(cwd=...)` inherits the parent's stale PWD → OpenCode bound
  the REPO as project, ignored the sandbox `opencode.json`, and the model
  grep'd gold answers out of `data/calib.json`. Fix pattern (already in
  run_real.py): `git init` the sandbox AND pass `env={**os.environ,
  "PWD": sandbox}`.
- **OpenCode `permission: {bash: "deny"}` does NOT reliably block bash.**
  `tools: {bash: false, ...}` in opencode.json is what actually removes the
  tool (verified live). Keep both.
- **OpenCode sessions can die silently on provider errors** (exit 0, truncated
  event stream, no final text). run_real.py captures stderr per run, retries
  once, and marks still-empty runs `failed` (excluded from paired scoring).
- **CC headless (`claude -p`) will not run project `.claude/settings.json`
  hooks from an untrusted dir** — pass `--settings <file>` explicitly.
- **CC hook stdout must be `{"hookSpecificOutput": {"hookEventName": ...,
  "additionalContext": ...}}`** — a flat additionalContext is silently ignored.
- **CC transcript dedup key is `message.id`** (multiple JSONL lines per turn,
  same id, identical usage). uuid dedup double/triple-counts.
- **User's global `~/.claude/settings.json` allow-list OVERRIDES
  `--allowedTools ""`** — sandboxes must be empty-or-controlled CWDs plus hard
  `--disallowedTools`; and audit tool inputs for out-of-sandbox paths anyway
  (run_real.py `outside_sandbox_refs`).
- Experiment reruns are resumable: run_real.py skips questions with successful
  rows, re-attempts failed ones.
