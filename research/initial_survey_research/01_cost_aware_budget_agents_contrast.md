# Category 1 Contrast Table: Cost-Aware & Budget-Constrained Agent Frameworks

How each paper relates to / contrasts with aspects of our monitor-agent-as-reward-model proposal.

| Paper | Our Motivation (cost-aware stopping) | Our Approach (monitor agent as reward model) | Our Solution (learned soft stopping curve) | Key Difference |
|-------|--------------------------------------|----------------------------------------------|-------------------------------------------|----------------|
| **BATS** | BATS shares the goal of budget-aware agent behavior and has a "dig deeper vs. pivot" decision. | BATS uses prompt-level budget tracking and heuristic verification modules — no separate model, no reward signals. | BATS uses fixed high/medium/low budget regime heuristics, not a learned curve. | BATS is training-free; we propose training a separate monitor. |
| **BAVT** | BAVT directly addresses budget-conditioned step selection with an explore/exploit trade-off based on remaining budget. | BAVT uses LLM self-evaluation for residual value prediction — no separate monitor model. | BAVT's budget exponent is a fixed mathematical function, not a learned function of reasoning quality. | BAVT is training-free and uses a single LLM backbone; we train a separate monitor. |
| **INTENT** | INTENT separates intention-level planning from execution — a hierarchical structure similar to our monitor-executor split. | INTENT's world model is learned from static trajectory data, not trained via RL as a reward model. | INTENT enforces hard budget feasibility (if exceeds budget → block), not a soft learned stopping curve. | INTENT is inference-time only with a learned world model; we propose RL-based monitor training. |
| **IterResearch** | IterResearch trains agents with efficiency-aware policies, directly addressing the cost-quality trade-off. | IterResearch uses discounted reward shaping embedded in the policy's RL training — no separate monitor. | A fixed discount factor provides a static efficiency penalty, not a learned dynamic stopping curve. | Our monitor is separate and specialized; IterResearch embeds efficiency in the policy. |
| **Trajectory Reduction** | Confirms that later steps are most redundant — empirical support for the value of early stopping. | Post-hoc redundancy detection — no real-time monitor, no training signals for the executor. | Removes redundancy after generation, not learned stopping during generation. | Our approach prevents wasted computation; trajectory reduction removes it after the fact. |
| **SMART** | Addresses tool overuse — the "when to stop using tools" problem from a self-awareness perspective. | Trains the agent itself to recognize knowledge boundaries — no external monitor. | Binary "tool needed / not needed" decision, not a continuous cost-benefit curve. | Self-assessment vs. external monitoring — we argue an external monitor is more reliable. |
| **Stop Wasting Tokens** | Has a SupervisorAgent that decides when and how to intervene — architecturally closest to our monitor. | Heuristic-based risk detection and prompt-based supervision — no learned reward model. | Binary intervention decisions (intervene / don't intervene), not a soft learned curve. | Operates at multi-agent orchestration level; our monitor operates within single-agent reasoning. |
| **AutoTool** | Addresses tool selection cost, which is one budget dimension our monitor would track. | Graph-based tool search — no monitor, no reward model, no stopping decisions. | No stopping decisions at all — only tool selection optimization. | Addresses a different problem (tool selection efficiency), not stopping decisions. |

**Summary:** All papers in this category address budget awareness but use **training-free heuristics, fixed thresholds, or prompt-based interventions**. None trains a separate model to make cost-aware stopping decisions, and none provides a process-level reward signal for executor training. Our proposal fills the gap between these heuristic approaches and the RL-based training methods in Category 4.
