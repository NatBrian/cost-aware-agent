### Plan-and-Act: Improving Planning of Agents for Long-Horizon Tasks

- **Authors:** (Multiple authors, 2025)
- **Year/Venue:** 2025, arXiv preprint
- **URL:** https://arxiv.org/abs/2503.09572

**Background:** LLM agents for long-horizon tasks need both planning (deciding what to do) and execution (carrying out the plan). Prior work either uses static plans that cannot adapt or reactive approaches that lack foresight.

**Motivation:** How can agents plan effectively for long-horizon tasks while dynamically adapting to unexpected observations?

**Approach:** Plan-and-Act separates planning and execution into distinct components: **(1) Planner:** Generates a structured plan as a sequence of sub-goals. The plan is both grounded (each step maps to specific actions) and expandable (sub-goals can be refined as more information becomes available). **(2) Executor:** Carries out the plan step-by-step, interacting with the environment (e.g., web navigation) to achieve each sub-goal. **(3) Dynamic Replanning:** When the executor encounters unexpected states or failures, the system triggers replanning — the planner revises the remaining sub-goals based on new information. The approach uses synthetic data generation to create training data: action trajectories are generated by executing agents, then grounded plans are extracted by a stronger model. Chain-of-thought reasoning is integrated into both planning and execution.

**Training Method:** SFT on synthetic plan-and-act trajectories. Plans generated by stronger models; execution traces from agent rollouts. Dynamic replanning trained via synthetic perturbations.

**Key Results:** Improves performance on WebArena and WebVoyager benchmarks. Dynamic replanning significantly outperforms static plans. The separation of planning and execution enables more coherent long-horizon behavior.

**Weakness:** The planner and executor are both LLM-based — the overhead of two LLM calls per step is significant. Synthetic data generation quality depends on the teacher model.

**Relevance to Our Work:** **Medium.** Plan-and-Act's planner-executor separation mirrors our monitor-executor architecture. The dynamic replanning mechanism is analogous to our monitor's "adjust approach" decision. Our monitor could extend Plan-and-Act by deciding whether to trigger replanning based on cost-benefit analysis.

### The Evolution of Tool Use in LLM Agents: From Single-Tool Call to Multi-Tool Orchestration

- **Authors:** (Multiple authors, 2025)
- **Year/Venue:** 2025, arXiv preprint
- **URL:** https://arxiv.org/abs/2603.22862

**Background:** LLM agents have evolved from single-tool callers to multi-tool orchestrators. This evolution has outpaced systematic understanding of the design space.

**Motivation:** What are the key design dimensions for multi-tool agents, and how do different approaches trade off capability against cost?

**Approach:** A comprehensive survey and taxonomy of multi-tool agent design. The paper categorizes approaches along several dimensions: **(1) Inference-Time Paradigms:** Topological planning (tool DAG construction), long-horizon orchestration (sequential tool chaining), and agent self-improvement (reflection on tool use). **(2) Tuning Paradigms:** SFT on tool-use demonstrations, RL for tool selection, and hybrid approaches. **(3) Cost Considerations:** The survey explicitly analyzes the cost implications of different multi-tool paradigms — noting that each additional tool in the prompt adds token cost, each additional tool call adds latency and API cost, and complex orchestration adds reasoning overhead.

**Training Method:** Survey paper — covers SFT, RL, inference-time methods across surveyed works.

**Key Results:** Identification of key trade-offs: topological planning reduces redundant calls but adds planning overhead; RL improves tool selection accuracy but requires training; long-horizon orchestration improves task completion but increases cost. The survey highlights the lack of cost-aware tool orchestration methods.

**Weakness:** Survey paper — no new method proposed. The rapidly evolving field means some recent work may be missing.

**Relevance to Our Work:** **Medium-High.** This survey explicitly identifies the lack of cost-aware tool orchestration as a gap — directly motivating our work. The taxonomy of tool-use paradigms provides a framework for situating our monitor agent within the broader tool-use landscape.

### To Call or Not to Call: A Framework to Assess and Optimize LLM Tool Calling

- **Authors:** (Multiple authors, 2025)
- **Year/Venue:** 2025, arXiv preprint
- **URL:** https://arxiv.org/abs/2605.00737

**Background:** LLM agents face the fundamental decision of whether to call a tool or rely on internal knowledge. This decision has significant cost implications — unnecessary tool calls waste resources, while missed tool calls can lead to incorrect answers.

**Motivation:** Can we build a framework that assesses when tool calling is actually necessary and optimizes the tool-calling decision?

**Approach:** A framework for assessing and optimizing LLM tool calling. The approach has two components: **(1) Necessity Assessment:** For a given query, the framework evaluates whether a tool call is necessary by analyzing the query's knowledge requirements, the model's internal knowledge boundaries, and the potential value of external information. This uses a combination of model confidence estimation and knowledge probing. **(2) Optimization:** The tool-calling decision is formulated as a cost-benefit optimization — call the tool if the expected improvement in answer quality justifies the tool's cost. The framework includes a learned cost model that estimates both the direct cost (API fee, latency) and the indirect cost (additional context length, potential for error propagation) of each tool call.

**Training Method:** The necessity assessor uses model confidence estimation and knowledge probing techniques. The cost model may be learned from historical tool-use data.

**Key Results:** Systematic assessment of when tools are necessary reveals that many tool calls are avoidable. The cost-benefit optimization reduces unnecessary tool calls while maintaining answer quality.

**Weakness:** Knowledge boundary estimation is inherently uncertain. The cost model requires accurate API pricing data. Only tested on knowledge-retrieval tool calls.

**Relevance to Our Work:** **Medium-High.** "To Call or Not to Call" applies cost-benefit analysis to individual tool-call decisions — directly analogous to how our monitor would apply cost-benefit analysis to stopping decisions. The learned cost model concept maps to our monitor's cost estimation function.

### DeepResearcher: Scaling Deep Research via Reinforcement Learning in Real-world Environments

- **Authors:** (Multiple authors, 2025)
- **Year/Venue:** 2025, arXiv preprint
- **URL:** https://arxiv.org/abs/2504.03160

**Background:** Deep research tasks require agents to search the web, browse pages, synthesize information, and produce comprehensive answers. These tasks involve dozens of tool calls and thousands of tokens, making cost a critical concern.

**Motivation:** Can RL train agents to perform deep research in real-world web environments, learning efficient search and synthesis strategies?

**Approach:** DeepResearcher is an RL-trained agent for deep research tasks. The agent operates in a loop: **(1) Reasoning:** The agent analyzes the current state and decides what to do next. **(2) Web Search:** Queries a search engine with refined search terms. **(3) Web Browsing:** Browses relevant pages, extracting key information. **(4) Answering:** When sufficient information is gathered, generates a comprehensive answer. The training uses GRPO with outcome-based rewards (answer quality measured against ground truth). Key challenges addressed: high-concurrency requests handling, web crawling and API limitations, and dynamic real-world web environments. The agent learns to balance search breadth against depth and to recognize when enough information has been gathered.

**Training Method:** GRPO with outcome-based rewards. Real-world web search and browsing environment. Training on diverse deep research queries.

**Key Results:** RL-trained agent outperforms prompt-based baselines on deep research benchmarks. The agent learns efficient search strategies — fewer queries, more targeted browsing. Emergent behavior: the agent learns to stop searching when information is sufficient, even without explicit stopping rewards.

**Weakness:** Real-world web training is expensive and slow. Search engine API costs during training are significant. The agent's behavior depends on search engine quality.

**Relevance to Our Work:** **High.** DeepResearcher is a prime example of where our monitor agent would add value — the agent already learns to stop searching implicitly, but our monitor would make this explicit, trainable, and more reliable. Deep research tasks are the ideal testbed for cost-aware stopping.

### ReTool: Reinforcement Learning for Strategic Tool Use in LLMs

- **Authors:** Jiazhan Feng, Shijue Huang, Xingwei Qu, Ge Zhang, Yujia Qin, Baoquan Zhong, et al.
- **Year/Venue:** 2025, arXiv preprint
- **URL:** https://arxiv.org/abs/2504.11536

**Background:** Reasoning models excel at textual reasoning but struggle in structured problem-solving (geometry, computation, complex equations) where computational tools like code interpreters have clear advantages.

**Motivation:** Can RL teach a model when and how to invoke tools during reasoning, enabling autonomous discovery of optimal tool-use strategies without human priors?

**Approach:** ReTool enables dynamic interleaving of real-time code execution within natural language reasoning. The training framework has two phases: **(1) Synthetic cold-start:** Generate code-augmented long-form reasoning traces using a teacher model, producing supervised fine-tuning data. **(2) RL training:** Policy rollouts with multi-turn real-time code execution, using task outcome (answer correctness) as reward via GRPO. During RL, the model generates reasoning + optional code blocks; executed code results are fed back into the context; the model continues reasoning. The RL objective learns to decide autonomously when to invoke tools. Emergent behaviors include "code self-correction" — the model detects execution errors and retries with fixed code — and an "aha moment" where it spontaneously masters adaptive tool use.

**Training Method:** SFT on synthetic code-augmented traces, then GRPO with outcome-based rewards from code execution results and final answer correctness.

**Key Results:** 67% on AIME with 400 steps (vs. 40% for text-only RL at 1080 steps). Extended settings: 72.5%, surpassing OpenAI o1-preview by 27.9%.

**Weakness:** Synthetic cold-start data may bias tool-use patterns; focused on math/code execution tools only; requires sandboxed code execution environment.

**Relevance to Our Work:** **Relevant.** ReTool shows that RL can teach models an emergent when-to-use-tools strategy, which parallels our goal of teaching a model when-to-stop. The cold-start + RL training paradigm is a viable training recipe for our monitor.

### ToolRL: Reward is All Tool Learning Needs

- **Authors:** Cheng Qian, Emre Can Acikgoz, Qi He, Hongru Wang, Xiusi Chen, Dilek Hakkani-Tür, Gokhan Tur, Heng Ji
- **Year/Venue:** 2025, arXiv preprint
- **URL:** https://arxiv.org/abs/2504.13958

**Background:** SFT-based tool-use training struggles to generalize to unfamiliar or complex scenarios. RL offers better generalization but reward design for tool use is uniquely challenging — multiple tools with diverse parameters, coarse answer-matching rewards, and format correctness requirements.

**Motivation:** What reward designs work best for tool selection and application in the RL paradigm? A systematic study was missing.

**Approach:** First comprehensive study of reward design for tool-use RL. The authors systematically explore reward strategies across multiple dimensions: (1) Type — answer accuracy, format correctness, execution success; (2) Scale — absolute values, normalization approaches; (3) Granularity — trajectory-level, turn-level, step-level; (4) Temporal dynamics — static weights, curriculum-based reward shaping. They propose a principled multi-component reward: R = R_answer + α·R_format + β·R_execution, with carefully tuned weights and dynamic scaling as training progresses. The reward is used with GRPO for policy optimization.

**Training Method:** GRPO with the designed multi-component reward. SFT baseline available for comparison. Training data: tool-use queries with ground-truth answers.

**Key Results:** 17% improvement over base models, 15% over SFT models. The multi-component reward significantly outperformed single-component alternatives. Proper reward scaling and granularity were critical for stable training.

**Weakness:** Reward weights need task-specific tuning; format rewards may not transfer across tool schemas; relies on executable verification environments.

**Relevance to Our Work:** **Key relevance.** ToolRL's systematic reward design approach directly informs our reward function for a cost-aware monitor. The multi-component structure (task quality + format correctness + execution success) maps to our goal of balancing answer quality with computational cost. The finding that reward granularity matters supports using step-level rather than trajectory-level cost signals.

### RRO: LLM Agent Optimization Through Rising Reward Trajectories

- **Authors:** Zilong Wang, Jingfeng Yang, Sreyashi Nag, Samarth Varshney, Xianfeng Tang, Haoming Jiang, et al.
- **Year/Venue:** 2025, arXiv preprint
- **URL:** https://arxiv.org/abs/2505.20737

**Background:** Process Reward Models are powerful for providing step-level guidance but are extremely costly to scale because training data requires per-step trajectory exploration for every next-action candidate.

**Motivation:** Instead of exhaustively exploring all next-action candidates, can we focus on the relative reward trend across steps — specifically, ensuring rewards are increasing as the trajectory progresses?

**Approach:** RRO maintains an "increasing reward" criterion: at each reasoning step, it incrementally augments process supervision until finding a step where the reward differential (current step reward minus previous step reward) is positive. This "rising reward" signal identifies high-quality trajectory segments without exhaustive exploration. The method dynamically expands the search space for next-action candidates only when the reward trend suggests it's beneficial. RRO provides mathematical grounding for why rising reward trajectories correlate with task success, drawing on the monotonicity properties of optimal policies in MDPs. Training uses DPO-style preference learning with step-level preference pairs constructed from trajectories with rising vs. non-rising reward patterns.

**Training Method:** Process supervision with DPO-style preference learning. Step-level preference pairs from rising vs. non-rising reward patterns.

**Key Results:** RRO achieves superior performance over standard PRM approaches while requiring significantly less exploration cost. The rising reward signal efficiently identifies high-quality trajectory segments.

**Weakness:** The rising reward assumption may not hold for all tasks (e.g., tasks requiring backtracking or exploration); tested only on relatively short-horizon tasks.

**Relevance to Our Work:** **Relevant.** The rising reward concept provides a signal for when an agent should continue vs. stop: diminishing or negative reward deltas suggest the trajectory has plateaued and additional steps yield little benefit. This is precisely the cost-benefit trade-off we want our monitor agent to model.

### CARL: Critical Action Focused Reinforcement Learning for Multi-Step Agent

- **Authors:** Leyang Shen, Yang Zhang, Chun Kai Ling, Xiaoyan Zhao, Tat-Seng Chua
- **Year/Venue:** 2025, arXiv preprint
- **URL:** https://arxiv.org/abs/2512.04949

**Background:** GRPO assumes each action in a trajectory contributes equally, which is fundamentally untrue for multi-step agents. Preliminary analysis shows >50% of actions induce near-zero change in final reward when resampled.

**Motivation:** Can we design an RL algorithm that concentrates optimization on high-criticality actions while excluding low-criticality ones, improving both performance and efficiency?

**Approach:** CARL estimates action criticality via model confidence (the policy's own probability of the action). High-confidence deterministic actions are marked as low-criticality; low-confidence/uncertain actions (where the model is unsure) are high-criticality, as these are the decision points. CARL then: (1) performs rollouts only from critical steps forward (not from scratch), computing action-level rewards as expected outcome gains; (2) updates the model only on high-criticality actions, excluding low-criticality steps from the policy gradient. This dual focus (selective rollouts + selective updates) dramatically reduces redundant sampling and noisy reward signals. 60.4% fewer training samples needed vs. GRPO.

**Training Method:** Modified GRPO variant. At each training step: identify critical actions → rollout from critical action points → compute action-level advantages → update only on critical actions.

**Key Results:** Higher accuracy than GRPO while using <50% of inference tokens and 39.6% of training samples. Consistent improvements across model sizes and types.

**Weakness:** Model confidence as a criticality proxy may be imperfect; requires environments where actions can be meaningfully resampled from intermediate states; focused on search agents only.

**Relevance to Our Work:** **Directly relevant.** CARL's critical action identification via model confidence directly parallels our "stop vs. continue" decision point. When a monitor agent is uncertain about whether to stop, that decision is high-criticality per CARL's framework. The selective optimization approach supports efficient cost-aware training.
